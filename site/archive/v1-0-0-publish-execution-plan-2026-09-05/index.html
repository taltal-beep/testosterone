    v1.0.0 Publish Execution Plan — 2026-09-05¶

    Index · Publish Readiness Assessment - 2026-07-24 · V1 Release Roadmap · Publishing to PyPI · Publishing Docker Images

    Purpose: The single working checklist that takes testo-core from unreleased 0.1.0 to a published, installable v1.0.0 on PyPI, GHCR, and JFrog Artifactory. Supersedes as the action list: Publish Readiness Assessment - 2026-07-24 (that note stays as the point-in-time analysis; this note is what we execute). Method: One step at a time, top to bottom. A step is not done until its Done when line is true. Check boxes as we go and commit the doc with the change it describes.

    Owner legend¶

    • AI — Claude does it in-session.
    • YOU — needs your credentials, 2FA, or org admin. Cannot be delegated.
    • BOTH — AI drives, you approve or watch.

    Step 1 — Streamlit decision¶

    The React frontend is the official UI (Phase 3 gates 100%). testo_ui/, the testo-ui entrypoint, and streamlit>=1.36.0 are still shipped. See Streamlit to React Migration Guide.

    Pick one:

    • [x] A — Deprecate (chosen 2026-09-05): emit a DeprecationWarning on testo-ui entry, note it in CHANGELOG.md and README.md, schedule removal for v1.1. ~30 min.
    • [ ] ~~B — Remove now:~~ (deferred to v1.1) drop testo_ui/, the entrypoint, the [ui] extra, and the streamlit dependency. Shrinks install surface but touches packaging contract tests. ~2h.

    Done when: the choice is implemented, tests still green, and CHANGELOG.md records it.

    Step 3 — PyPI publish auth — YOU¶

    publish.yml is release-triggered and uses OIDC trusted publishing (no long-lived token). It has never fired. Without this step, the first release run fails at the publish job. See Publishing to PyPI.

    • [ ] Register/claim the testo-core project name on PyPI
    • [ ] Add a trusted publisher: repo taltal-beep/testosterone, workflow publish.yml, environment pypi
    • [ ] Repeat on Test PyPI with environment test-pypi
    • [ ] Create GitHub Actions environments test-pypi and pypi (Settings → Environments)

    Done when: both environments exist in GitHub and both trusted publishers are registered.

    Name availability — checked 2026-09-05: testo-core is free on PyPI (HTTP 404, unregistered). No fallback name needed. Note that testosterone is taken, so the distribution name stays testo-core as already configured.

    Step 4 — GHCR permissions — YOU¶

    docker-publish.yml pushes ghcr.io/<owner>/testo-runner on release. See Publishing Docker Images.

    • [ ] Confirm the release job has packages: write
    • [ ] Confirm Actions is allowed to publish packages for this repo/org
    • [ ] Decide package visibility (public for OSS)

    Done when: repo settings permit a GHCR push from Actions.

    Step 5 — Tag, release, firefight¶

    This is the step that actually ships. Both publish workflows fire off the GitHub Release event.

    • [ ] Create annotated tag v1.0.0 on main
    • [ ] Push the tag
    • [ ] Publish a GitHub Release with the [1.0.0] changelog section as notes
    • [ ] Watch publish.yml — Test PyPI dry-run → PyPI
    • [ ] Watch docker-publish.yml — GHCR push
    • [ ] Fix whatever fails on first run and re-run

    Done when: both workflows are green.

    Two release-blocking workflow bugs were already found and fixed on 2026-09-05 (see Session log) — the first-run failure budget is now smaller, but not zero.

    Expect one failure cycle. These workflows have literally never executed. Budget for it rather than being surprised. If a fix requires a code change, the tag must be deleted, moved, and the release re-cut.
